# CSV ID 규칙

## 1. 문서 목적

이 문서는 프로젝트에서 사용하는 CSV 데이터의 `idx` 작성 규칙을 정의한다.

모든 CSV 작성자와 작업자는 동일한 ID 구조와 종류별 범위를 사용하여 서로 다른 데이터 테이블 사이의 ID 중복을 방지한다.

## 2. 기본 형식

- `idx`에는 숫자만 사용한다.
- ID는 개념적으로 `CCCIII` 형식의 6자리 숫자로 구성한다.
- 앞의 세 자리 `CCC`는 데이터 종류 ID를 나타낸다.
- 뒤의 세 자리 `III`는 해당 데이터 종류 안에서 사용하는 고유 ID를 나타낸다.
- 하나의 완성된 ID는 `데이터 종류 ID × 1000 + 고유 ID`로 계산한다.

| 구분 | 자리 | 의미 |
|---|---:|---|
| 데이터 종류 ID | 앞 3자리 | CSV 또는 데이터 테이블의 종류 |
| 고유 ID | 뒤 3자리 | 같은 종류 안에서 각 데이터를 구분하는 값 |

CSV에서 ID를 숫자형으로 읽으면 앞쪽의 `0`은 값에 포함되지 않을 수 있다. 예를 들어 `001001`과 `1001`은 같은 숫자 ID로 취급한다. 앞쪽 0은 형식을 읽기 쉽게 표시할 때만 사용하며 별개의 ID를 뜻하지 않는다.

## 3. 데이터 종류 ID

- 데이터 종류마다 서로 다른 세 자리 종류 ID를 배정한다.
- 종류 ID는 `001`부터 `999` 범위에서 사용한다.
- 이미 다른 CSV 또는 데이터 테이블에 배정된 종류 ID를 다시 사용하지 않는다.
- 새로운 CSV 종류를 추가하기 전에 기존 종류 ID와 예약된 범위를 확인한다.
- 배정된 종류 ID는 코드의 `DataTableType` 값 및 로더 분류 규칙과 일치해야 한다.

종류 ID의 실제 배정과 예약 현황은 Google Docs의 [CSV 종류 ID](https://docs.google.com/document/d/1lCzaQRmFRWrxfIhWr2UZy64-7A8v1N9fAvlOorMF77E/edit?tab=t.kh9qpvlz4raf) 문서를 단일 권위 목록으로 사용한다.

- 새로운 종류 ID를 배정하거나 기존 배정을 변경할 때는 해당 Google Docs 문서를 갱신한다.
- CSV, `DataTableType` 또는 loader를 구현하기 전에 해당 문서에서 종류 ID의 중복과 예약 여부를 확인한다.
- 저장소의 규칙 문서나 개별 코드 주석에 종류 ID 목록을 별도로 복제하지 않는다.

## 4. 종류별 고유 ID

- 고유 ID는 각 데이터 종류 안에서 `001`부터 `999` 범위로 배정한다.
- 같은 종류 ID 안에서는 동일한 고유 ID를 중복해서 사용할 수 없다.
- 삭제되거나 사용이 중단된 ID는 참조 및 저장 데이터 호환성을 확인하기 전까지 다른 데이터에 재사용하지 않는다.
- 표시명, 파일명 또는 CSV 행 순서를 고유 ID 대신 사용하지 않는다.
- 새로운 ID를 배정하기 전에 대상 종류의 기존 ID와 예약된 ID를 확인한다.

## 5. 작성 및 검증 절차

1. 추가할 데이터가 속한 종류 ID를 확인한다.
2. 해당 종류에서 사용 중이거나 예약된 고유 ID를 확인한다.
3. 종류 ID와 고유 ID를 결합해 `idx`를 작성한다.
4. 같은 CSV 안의 중복과 다른 CSV에 배정된 종류 범위 침범 여부를 검사한다.
5. DTO의 `idx` 자료형, `DataTableType`, parser와 loader routing이 같은 규칙을 사용하는지 확인한다.
6. 병합 직전에 최신 기본 브랜치를 기준으로 ID 중복을 다시 검사한다.

규칙에 맞지 않거나 중복된 ID가 발견되면 해당 CSV를 런타임 데이터로 등록하지 않고 원인을 수정한 뒤 다시 검증한다.
