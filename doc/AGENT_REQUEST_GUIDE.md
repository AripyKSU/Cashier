# 자연어 작업 요청 변환 지침

이 문서는 사용자의 목적 중심 자연어 요청을 프로젝트 규칙에 맞는 실행 프롬프트 초안으로 변환하는 방법을 정의한다.

공통 작업 규칙은 [`AGENTS.md`](../AGENTS.md), 역할과 권한은 [`TEAM_ROLES.md`](TEAM_ROLES.md), CSV 작업은 [`DATA_RULES.md`](DATA_RULES.md), Prefab과 리소스 작업은 [`PREFAB_RESOURCE_RULES.md`](PREFAB_RESOURCE_RULES.md)를 따른다.

## 적용 대상

다음처럼 목적만 제시된 요청에 적용한다.

- "물건 계산 시스템을 설계 및 생성"
- "상점에 새로운 상품을 추가"
- "계산대 Prefab을 만들어 데이터와 연결"

사용자가 충분한 작업 명세를 제공했다면 불필요하게 다시 확장하지 않는다.

## 변환 원칙

- 요청 목적과 범위를 임의로 확대하지 않는다.
- 기존 코드, CSV, Prefab, Scene과 Addressables를 읽기 전용으로 조사한다.
- 사용자 지시·문서·저장소에서 확인된 정보는 `확정`으로 표시한다.
- 기존 구현을 근거로 적용한 안전한 기본값은 `추론`으로 표시하고 근거를 남긴다.
- 결과를 바꾸는 기획, 권한, ID, PK·FK, 삭제와 migration은 추측하지 않고 `미확정`으로 표시한다.
- 초안 작성은 구현, 파일 수정, 승인 또는 권한 위임을 의미하지 않는다.
- 사용자 또는 승인권자가 초안을 확인한 뒤 실제 작업을 시작한다.

| 상태 | 의미 | 처리 |
|---|---|---|
| `확정` | 사용자 지시, 문서 또는 저장소에서 확인됨 | 실행 프롬프트에 직접 반영 |
| `추론` | 기존 구현을 근거로 한 안전한 기본값 | 근거와 함께 제안 |
| `미확정` | 결과나 권한을 바꿀 수 있음 | 질문 또는 placeholder로 유지 |
| `해당 없음` | 현재 작업과 관계없음 | 실행 범위에서 제외 |

## 변환 절차

1. 요청의 최종 결과, 대상 기능과 사용자에게 보이는 동작을 추출한다.
2. 관련 코드, 데이터, Prefab, Scene, Addressables와 기존 시스템을 조사한다.
3. 필요한 역할, 담당자, 허용 경로와 생성·수정·이동·삭제 범위를 정리한다.
4. 일반 변경과 공용·보호·아키텍처 변경을 구분한다.
5. 작업별 구현 조건과 완료 검증을 작성한다.
6. 확정·추론·미확정 정보를 구분한다.
7. 미확정 항목을 해결하기 전에도 안전하게 수행 가능한 작업과 차단할 작업을 분리한다.
8. 사용자에게 1단계 검토 요약만 제시하고 승인을 기다린다.
9. 승인 후 관련 항목만 포함한 2단계 실행 프롬프트를 내부 작업 명세로 구성해 수행한다.

## 반드시 확인할 항목

다음 항목은 임의로 확정하지 않는다.

- 가격 자료형, 반올림, 할인처럼 결과를 바꾸는 기획 규칙
- 승인된 CSV ID 범위, PK와 FK
- 원본 삭제와 기존 데이터 migration
- Package와 ProjectSettings 변경
- 공용 Manager·API의 기본 branch 반영
- 기준이 없는 최초 Prefab의 필수 구조
- 여러 구현 중 선택에 따라 사용자 동작이 달라지는 경우

파일 위치, 기존 API 재사용, 코드 스타일과 이름처럼 저장소에서 안전하게 확인할 수 있는 항목은 별도 질문 없이 `추론`으로 제안할 수 있다.

## 사용자 표시와 내부 실행 명세

- 자연어 요청을 받으면 채팅에는 1단계 검토 요약만 표시한다.
- 사용자 승인 전에는 읽기 전용 조사 외의 변경을 수행하지 않는다.
- 승인 후 승인된 요약과 관련 명세를 바탕으로 2단계 실행 프롬프트를 내부 작업 명세로 구성한다.
- 2단계 실행 프롬프트는 채팅에 출력하지 않아도 된다.
- 내부 작업 명세는 승인된 목적·범위를 확대하거나 새로운 권한을 부여할 수 없다.
- 실행 중 승인 범위를 벗어난 변경이 필요하면 해당 변경만 중단하고 추가 승인을 요청한다.
- 완료 보고에는 실제 변경 범위, 검증 결과와 승인 범위 밖에서 보류한 항목을 기록한다.

처리 흐름은 다음과 같다.

```text
자연어 요청
→ 1단계 검토 요약 표시
→ 사용자 승인
→ 2단계 실행 프롬프트 내부 구성
→ 작업 수행
→ 검증 및 결과 보고
```

## 1단계 검토 요약

사용자가 작업 진행 여부를 판단하는 데 필요한 내용만 표시한다.

```md
# 작업 제안

- 목적:
- 예상 작업 범위:
- 제외 범위:
- 중요한 가정:
- 보호 변경과 검토:
- 미확정 또는 차단 조건:
- 최소 검증:

이 범위로 진행할까요?
```

해당하지 않는 항목은 생략한다. 사용자가 `승인`, 범위 변경 또는 조건부 승인을 명시할 수 있을 만큼만 작성한다.

## 2단계 실행 프롬프트

승인 후 다음 항목 중 실제 작업에 필요한 것만 내부 작업 명세에 포함한다.

- 목적과 필수 동작
- 권한 대행 참여자와 적용 역할
- 생성·수정이 허용된 경로와 금지 범위
- 사용할 기존 시스템과 작업별 제약
- 보호 변경, 검토자와 승인 기록 위치
- 필요한 최소 컴파일·실행·데이터·Prefab 검증
- 임의로 결정하지 않을 차단 조건

공통 규칙을 반복하지 않고 적용할 문서 경로만 참조한다. CSV나 Prefab이 실제 변경 대상이 아니면 해당 규격을 포함하거나 읽도록 요구하지 않는다. `해당 없음`, 상세 조사 기록과 구현 결정에 영향이 없는 정보는 실행 프롬프트에서 생략한다.

## 초안 생성 요청 예시

```text
"물건 계산 시스템을 설계 및 생성"이라는 요청을
doc/AGENT_REQUEST_GUIDE.md에 따라 분석하고,
1단계 검토 요약만 제시해줘.

아직 구현하거나 파일을 수정하지는 마.
내가 승인하면 2단계 실행 프롬프트를 내부 작업 명세로 구성해 수행해줘.
```
