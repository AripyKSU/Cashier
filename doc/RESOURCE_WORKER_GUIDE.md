# 리소스 작업자 작업 명세서

버전: 1.0  
적용 대상: 이미지·애니메이션·오디오·프리팹·데이터·번들 리소스를 제작, 가공, 연결하는 작업자 및 AI 작업자

## 1. 역할

리소스 작업자는 승인된 기획과 기술 명세를 실제 프로젝트 자산으로 변환하고, 런타임에서 사용할 수 있는 형태로 연결해 인계한다.

- 원본 리소스 제작 및 수급
- 파일 규격 변환과 최적화
- import 설정, slicing, pivot, 압축 설정
- 프리팹·애니메이터·데이터 직렬화 연결
- 리소스 로더·번들·주소 체계 등록
- 시각·구조·참조 무결성 검증
- 프로그래머와 QA 작업자에게 결과 인계

프로그래머 소유의 게임 로직과 타이밍을 임의로 구현하거나 변경하지 않는다.

## 2. 우선순위

1. 사용자 또는 책임자의 최신 명시적 지시
2. 저장소의 작업자 규칙
3. 승인된 기획·아트·기술 명세
4. 이 문서
5. 개인 관행

명세가 충돌하거나 리소스 제약 때문에 동일하게 구현할 수 없으면 임의 대체하지 않고 차이와 대안을 보고한다.

## 3. 작업 시작 게이트

- 대상 리소스, 사용 위치, 규격, 완료 조건, 수정 허용 범위를 확인한다.
- 기존 자산, 공용 material, sprite, prefab, animation, audio를 먼저 검색한다.
- 기존 자산 재사용과 신규 제작 중 비용이 낮고 명세를 충족하는 쪽을 선택한다.
- 원본 파일, 라이선스, 출처, 수정 가능 여부를 확인한다.
- 데이터 식별자, 파일 경로, 로더 범위, 참조 관계를 확인한다.
- 현재 브랜치와 dirty·untracked·stash 상태를 확인하고 무관한 자산을 보호한다.
- downstream 작업에 필요한 데이터와 원본이 준비되지 않았으면 제작을 시작하지 않는다.

## 4. 파일과 폴더 규칙

- 프로젝트의 기존 폴더 구조와 이름 규칙을 따른다.
- 표시명이나 임의 문자열을 런타임 식별자로 사용하지 않는다.
- 파일명은 역할, 대상, 동작, variant를 일관된 순서로 표현한다.
- 대소문자만 다른 파일을 만들지 않는다.
- 원본, 작업 파일, 최종 export 파일을 구분한다.
- 임시 파일과 생성 도구 출력은 제품 자산 폴더에 남기지 않는다.
- 파일 이동·이름 변경 시 참조와 메타데이터 식별자가 유지되는지 확인한다.
- 같은 목적의 단수·복수 폴더를 중복 생성하지 않는다.

## 5. 데이터와 리소스 연결

- 프로젝트가 정한 정수형 또는 명시적 식별자 규칙을 사용한다.
- 신규 행 추가 전 PK 대역, 중복, FK, parser, loader, router 범위를 감사한다.
- 개별 객체가 로더나 번들 API를 직접 우회 호출하지 않도록 기존 manager와 pooling 경로를 사용한다.
- CSV, prefab, animator, texture, address 등록을 같은 변경 단위에서 동기화한다.
- 파일명 기반 추론이나 header 검증 완화로 잘못된 routing을 숨기지 않는다.
- 참조 대상이 준비되지 않았으면 임의 ID나 임시 문자열로 활성화하지 않는다.
- 신규 ID 대역이 필요하면 사용 현황과 예상 필요량을 근거로 책임자와 협의한다.

## 6. 번들·Address 등록

- 기존 group, label, address 이름 규칙을 따른다.
- 동일 address, 중복 entry, 잘못된 GUID, 누락 dependency를 확인한다.
- address 변경 시 모든 소비자와 migration 영향을 함께 확인한다.
- 로컬 파일 존재만으로 런타임 로딩 성공을 주장하지 않는다.
- bundle build 또는 runtime load를 실행하지 않았다면 정적 검증으로만 보고한다.

## 7. 구조 검수

- 원본 파일과 메타데이터 파일이 1:1로 존재하는지 확인한다.
- GUID가 중복되거나 의도치 않게 변경되지 않았는지 확인한다.
- prefab과 데이터의 모든 직렬화 참조가 유효한지 확인한다.
- 사용되지 않는 임시 자산과 중복 리소스를 식별하되 승인 없이 삭제하지 않는다.
- 컴파일 오류와 제품 Console 오류를 분리해 기록한다.
- 정적 검사, import 성공, editor 표시, runtime 검증을 서로 구분한다.

## 8. 인계 규칙

인계 보고에는 다음을 포함한다.

- 제작·수정한 파일과 경로
- 원본 및 라이선스 정보
- 해상도, frame 수, PPU, pivot, 방향, import 설정
- prefab·animator·data·address 연결 관계
- PK·FK·GUID·중복 검사 결과
- 시각 검수 결과와 비교 기준
- 컴파일·Console·runtime 검증 상태
- placeholder, 미완성, 사용자 확인 대기 항목
- downstream 작업자가 수행해야 할 다음 단계

## 9. 금지 사항

- 승인되지 않은 리소스나 데이터 ID를 임의로 활성화하기
- 기존 자산을 확인하지 않고 동일 리소스를 새로 만들기
- 파일명이나 문자열로 런타임 routing을 우회하기
- 원본과 메타데이터의 짝을 깨뜨리기
- import 오류, missing reference, 예외를 숨겨 완료 처리하기
- 시각 검수 없이 생성 성공 응답만으로 인계하기
- 프로그래머 소유의 판정·타이밍·게임 로직을 이미지 frame에 고정하기
- 무관한 prefab, 데이터, 설정을 함께 수정·포맷·stage하기
- 승인 없이 원본 삭제, Git 병합, 배포, 외부 업로드 수행하기
