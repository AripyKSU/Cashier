# 20일 플레이 리밸런싱 실행 계획

> **현재 적용 상태**: 현재 저장소의 20일 밸런스는 이 계획 문서의 제안값이 아니라 [20일차 리밸런싱 적용 결과](20-day-rebalancing-result.md)에 기록된 실제 CSV·런타임 상태를 기준으로 잡혀 있다. 계획과 결과가 다를 경우 결과 문서의 적용값·검증 상태·후속 항목을 우선한다.

## 1. 목적과 범위

현재 31일·하루 180초 기준인 진행과 경제를 20일·하루 120초 구조로 압축한다. 단순히 날짜와 시간만 줄이지 않고 상품 가격, 설비 가격, 유지비, 상품 등장 확률과 엔딩·이벤트 날짜를 함께 조정한다.

목표는 다음과 같다.

- 전체 플레이가 반복적으로 늘어지지 않도록 최종일을 20일로 줄인다.
- 설비를 구매할수록 더 비싼 상품을 자주 판매해 매출이 크게 성장하는 느낌을 준다.
- 상위 상품이 무작위 추첨에서 계속 빠져 설비 투자가 무의미해지는 상황을 방지한다.
- 편의 설비와 상품 해금 설비의 가격 체계를 단계별로 이해하기 쉽게 정리한다.
- 유지비가 실제 투자와 안전 자금에 영향을 주는 지출로 기능하게 한다.
- 기존 시간대 조명 연출은 유지한다.

이번 문서의 가격은 1차 구현·플레이테스트용 기준값이다. `일 6건`을 중앙 처리량으로 20일 경제를 검증한 뒤 시민권 가격과 유지비를 우선적으로 2차 조정한다.

## 3. 감독관과 일일지침의 관계

3일차 감독관 이벤트는 “오늘부터 일일지침이 적용된다”는 사실을 안내하는 온보딩 이벤트다. 감독관 이벤트가 지침을 직접 생성하거나 판정하지 않는다.

- 감독관 표시 권위: `Assets/Datas/InspectorEventData.csv`
- 지침 개수 결정: `DailyGuidelineGenerator.GetGuidelineCount`
- 지침 생성·위반 판정: `DailyGuidelineGenerator`, `DailyGuidelineEvaluator`
- 벌금 계산: `DailyGuidelinePenaltyCalculator`

감독관 일정과 실제 지침 시작 날짜가 일치하도록 각각의 데이터와 코드를 함께 변경한다.

### 4.1 최종일 판정

대상:

### 4.2 시민권 구매 날짜

대상:

- `Assets/Scripts/Manager/GameSessionManager.cs`

3. 시민권 없이 20일 정산을 완료하면 Bad 엔딩을 확정한다.
4. 어떤 경로에서도 21일차를 생성하지 않는다.

## 7. 하루 영업시간

대상:

- `Assets/Scripts/Progress/DayProgress.cs`

현재:

```csharp
public const float DefaultBusinessDurationSeconds = 180f;
```

변경:

```csharp
public const float DefaultBusinessDurationSeconds = 120f;
```

`TimeOfDayUIController.fullCycleSeconds`는 디버그 자동 순환 값이므로 변경하지 않는다. 실제 시간대 연출은 `BusinessClockController`의 영업 진행률을 통해 120초에 맞춰 자동 압축되며, 사용자 결정에 따라 조명 곡선과 리소스는 현행을 유지한다.

관련 테스트와 문서의 기본 영업시간 기대값 `180f`를 `120f`로 갱신한다.

### 8.3 최고 단계 상품 최소 등장 보장

가중치만으로는 극단적인 불운을 제거할 수 없으므로 `DailyProductSelector.Select`에 최고 활성 단계 상품의 최소 등장 규칙을 추가한다.

처리 순서:

1. 현재 판매 가능한 상품을 해금 단계별로 분류한다.
2. 활성 상품이 존재하는 가장 높은 단계를 찾는다.
3. 해당 단계 상품을 먼저 비복원 추첨한다.
4. 남은 슬롯을 기존 단계 가중치 비복원 추첨으로 채운다.

| 당일 최대 상품 수 | 최고 활성 단계 상품 최소 등장 수 |
|---:|---:|
| 4종 | 1종 |
| 6종 | 2종 |
| 8종 | 2종 |

경계 조건:

- 구매했지만 아직 익일 활성되지 않은 설비 상품은 제외한다.
- 같은 상품을 중복 선택하지 않는다.
- 최고 단계 후보가 보장 수보다 적으면 가능한 상품만 선택한다.
- 보장 선택 후의 남은 상품은 기존 가중치 규칙을 사용한다.
- 일일지침은 최종 확정된 당일 상품 목록에서 생성한다.

## 15. 경제 시뮬레이션과 플레이테스트

### 15.1 오프라인 경제 비교

새 데이터를 적용한 뒤 다음 조건을 각각 충분한 seed로 계산한다.

- 하루 5건: 입문·실수 많은 플레이
- 하루 6건: 기준 밸런스
- 하루 7건: 숙련 플레이

각 조건에서 다음을 기록한다.

- 일별 매출과 유지비
- 일별 잔액
- 각 상품 설비 구매일과 활성일
- 각 편의 설비 구매일
- 가게 2·3단계 도달일
- 전체 필수 설비 완성일
- 시민권 구매 가능일과 20일 내 구매율
- 유지비 미납 및 GameOver 비율
- 일일지침 벌금
- 최고 단계 상품 최소 등장 규칙의 실제 노출 빈도

### 15.2 목표 범위

| 항목 | 목표 |
|---|---|
| 첫 상품 설비 | 2~3일 |
| 가게 2단계 | 6~7일 |
| 2단계 첫 상품 설비 | 7~9일 |
| 가게 3단계 | 12~13일 |
| 3단계 첫 상품 설비 | 13~14일 |
| 전체 필수 설비 완성 | 16~17일 |
| 시민권 구매 | 18~20일 |

업그레이드가 활성화된 다음 영업일 매출은 직전 3일 평균보다 최소 25~40% 증가하는 것을 체감 목표로 둔다.

### 15.3 실제 플레이 순서

전체 20일 플레이 전에 다음 구간을 나눠 확인한다.

1. 1~3일: 기본 상품, 첫 지침, 첫 설비 도달
2. 7~8일: 6종 상품, 2단계 설비, 편의 설비 가치
3. 13~14일: 8종 상품, 지침 2개, 3단계 고가 상품 노출
4. 18~20일: 유지비 압박, 시민권 구매, 엔딩 분기
5. 위 구간이 안정된 뒤 20일 연속 플레이

편의 설비별로 120초 안의 완료 거래 수와 거래당 평균 조작 시간을 측정한다. 상품 가격과 유지비가 맞아도 편의 설비가 거래량을 늘리지 못하면 해당 설비 가격 또는 효과를 별도로 재조정한다.

## 16. 실제 적용 순서

1. 최종일과 시민권 구매 날짜를 20일로 변경한다.
2. 기본 영업시간을 120초로 변경한다.

5. 상품 단계 가중치와 최고 단계 최소 등장 규칙을 구현한다.
6. `ProductData.csv`의 판매가와 원가를 교체한다.
7. `FacilityData.csv`의 전체 구매 가격을 교체한다.

11. 고정값·경계 테스트를 갱신하고 신규 상품 추첨 테스트를 추가한다.
12. Unity reimport와 컴파일 오류 0을 확인한다.
13. 관련 EditMode와 PlayMode 테스트를 실행한다.
14. 하루 5·6·7건 조건의 20일 경제 시뮬레이션을 실행한다.
15. 결과에 따라 시민권 가격과 유지비를 우선 2차 조정한다.
