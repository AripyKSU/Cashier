# 20일차 리밸런싱 적용 결과

> 기준: `GameplayBalance` 작업 트리의 현재 적용 상태
>
> 이 문서는 계획 문서의 제안값이 아니라 현재 저장소의 CSV·런타임 코드·검증 결과를 기록한 적용 결과 문서다. 현재 밸런스의 기준은 이 문서이며, 계획과 값이 다르면 이 문서의 실제 적용값을 우선한다.

## 1. 적용 요약

| 항목 | 현재 적용값 |
|---|---|
| 최종 영업일 | 20일차 |
| 1일 영업시간 | 120초 |
| 일일 상품 종류 | 1~6일차 4종, 7~12일차 6종, 13~20일차 8종 |
| 일일지침 | 1~2일차 0개, 3~12일차 1개, 13~20일차 2개 |
| 상품 카탈로그 | 16종 |
| 유지비 | 1~20일차 20행, 총 1,380,000G |
| 가격변동 이벤트 | 운영 이벤트 0건, 스케줄 0건 |
| 가격 기준 | 모든 상품의 당일 가격은 기본 판매가와 동일 |
| 최종일 처리 | 20일차 정산 후 다음 영업일을 만들지 않음 |

신문·라디오 가격변동 이벤트는 폐기된 상태다. 기능 API와 순수 계산기는 재활성화 여지를 위해 남아 있지만, 운영 CSV에 이벤트·스케줄 행이 없으므로 현재 플레이에서 후보 선정, 방송, 가격 변동이 발생하지 않는다. 가격변동률 값도 운영 데이터에 존재하지 않는다.

## 2. 진행·일일 콘텐츠

### 2.1 날짜와 영업시간

- `GameSessionManager.FinalDay = 20`
- `DayProgress.DefaultBusinessDurationSeconds = 120f`
- 코드의 경과일은 0부터 시작한다. 따라서 `elapsedDays = 0`이 표시 1일차이고, `elapsedDays = 19`가 표시 20일차다.
- 20일차 정산 완료 시 게임을 종료하며 21일차를 생성하지 않는다.
- 시민권은 게임오버가 아닌 정산 중에 구매할 수 있고, 최종일 정산을 통과할 수는 없다. 시민권 구매가 확정되면 도덕성에 따라 Good 또는 CitizenshipNegative 엔딩으로 즉시 종료한다.

### 2.2 일일지침

`Assets/Datas/DailyGuidelineData.csv`의 운영 규칙은 2행이다.

| 표시 일차 | 지침 수 | 운영 규칙 원본 |
|---:|---:|---|
| 1~2 | 0 | 적용하지 않음 |
| 3~12 | 1 | `rule_type=1`, `allowed_quantity=0` 또는 `rule_type=2`, `allowed_quantity=1`에서 추첨 |
| 13~20 | 2 | 위 두 규칙을 서로 충돌하지 않게 추첨 |

지침 후보는 당일 최종 상품 목록에서만 생성되며, 같은 상품 중복 선택은 허용하지 않는다.

### 2.3 당일 상품 추첨

현재 `DailyProductSelector` 적용값은 다음과 같다.

| 표시 일차 | 최대 상품 종류 | 기본/1/2/3단계 상대 가중치 | 최고 활성 단계 최소 보장 |
|---:|---:|---|---:|
| 1~6 | 4종 | 100 / 250 / 450 / 700 | 1종 |
| 7~12 | 6종 | 100 / 250 / 450 / 700 | 2종 |
| 13~20 | 8종 | 100 / 250 / 450 / 700 | 2종 |

- 현재 날짜에 활성화된 상품만 후보가 된다.
- 설비를 구매했더라도 활성일 전이면 해당 설비의 상품은 후보에서 제외한다.
- 최고 활성 단계 상품을 먼저 비복원 추첨하고, 남은 슬롯을 단계 가중치로 비복원 추첨한다.
- 상품 중복은 발생하지 않는다.

### 계획과 실제의 차이

계획 문서 10절에 적힌 가격은 1차 제안값이다. 현재 CSV는 그 제안과 다음처럼 다르다.

- 상품 해금 설비: 1단계가 80,000G·100,000G, 2단계가 350,000G·500,000G, 3단계가 750,000G·1,000,000G로 적용되어 있다.
- 시민권: 계획 제안 5,000,000G가 아니라 현재 CSV에서 3,000,000G로 적용되어 있다.
- 편의 설비와 가게 확장 가격은 계획 제안과 현재 CSV가 일치한다.

이 문서는 변경하지 않은 현재 적용 상태를 기록한다. 시민권 또는 상품 해금 설비를 계획 제안값으로 맞추려면 별도 밸런스 변경과 검증이 필요하다.
