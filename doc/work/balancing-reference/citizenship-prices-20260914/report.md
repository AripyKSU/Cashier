## 정책과 조건

- 시작금 1,000G, 31영업일, 매일 8/10/12건을 180초 안에 처리한다. 거래 간격은 기존 0.8~1.2 변동 가중치와 큐 입장·인내·이탈을 사용한다.
- 주문 전체를 제출 시점 현재가에 정가 판매하고 지침 위반 벌금을 낸다. 임의 거절, 폭리, 플레이 실수는 없다. 기존 가격 사건, 명성의 다음날 손님 구성 피드백, 운영비와 3일 미납 유예를 재사용한다. 매출에서 원가를 별도 자동 차감하지 않는다.
- 투자 순서는 `12001→12002→12007→12008→12003→12004→12009→12010→12005→12006→12011`이다. 단계 조건을 지키고 다음날 운영비를 남길 수 있을 때만 산다. 편의설비에 속도 효과를 부여하지 않았다.
- 11개 시설비 524,500G를 모두 실제 차감한 뒤 남은 현금이 비교 가격 이상이면 같은 정산에서 시민권을 차감하고 즉시 종료한다. 이 플레이 정책은 미납금을 먼저 갚고 미납 중 투자를 보류한다. 현재 `GameSessionManager` API의 시민권 구매 필수조건이라는 뜻은 아니다. 성공 뒤 영업 수익은 없다.
- 현재 CSV의 `12012` 가격은 1,000,000G지만 CSV를 바꾸지 않고 250,000/500,000/750,000/1,000,000/1,500,000G를 분석 매개변수로만 비교했다.

## 검증과 한계

검증 상태는 `PARTIAL`이다. `node calculate.js`로 15조건×10,000회=150,000개의 오프라인 31일 이하 경로를 실행했다. 시설 총비용·단계 순서, 10/11개 시설만 가진 경우와 가격보다 1G 부족한 경우의 구매 불가, 정확한 금액의 구매 가능, 일별 자금 보존, 성공일과 실제 처리일 수의 일치, 같은 seed 100개에서 25만 대비 150만의 경로별 비증가와 전체 15조건의 인접 가격별 성공률 비증가 assert가 통과했다. 기존 큐 경계 검사, 25개 과거 자금·명성 회귀, 30개 시설 활성 경로 검사도 다시 통과했다. `inputs.json`은 실행 시 읽은 CSV와 재사용 소스의 SHA256을 기록한다.

일일 거래·큐·명성·가격 사건·지침·정산은 기존 `citizenship-queue-20260913`의 `daySample`과 기존 정산 함수를 그대로 사용했다. 각 거래 수에서 모든 가격은 같은 seed를 써 가격 이외의 난수 조건을 맞췄다. 기존 모듈은 직접 실행하지 않아 과거 inputs/results를 덮어쓰지 않았다. 현재 FacilityData와 과거 비용 스냅샷을 비교해 기존 12001~12011 값이 모두 같고 추가 행이 12012 하나뿐이며 그 값이 1,000,000G임을 먼저 assert한 뒤, 새 분석 프로세스 안에서만 해당 행을 보완해 기존 모듈을 로드했다.

이 결과는 Unity PlayMode 150,000회나 사람 플레이 시험이 아니다. 처리 시간 분포, 정가 전량 판매·지침 위반 벌금 납부, 원가 자동 차감 없음, 투자 순서가 고정된 정책 조건부 결과다. UI 조작, 실제 실수, 재미와 구매 의향은 포함하지 않는다. 표의 0%와 100%는 10,000회 표본의 관측값이며 절대 불가능이나 보장을 뜻하지 않는다. 도덕성 0 이상 엔딩 분기는 긍정으로 확정됐으며 이 자금·선행 시설 달성률 계산에는 영향을 주지 않는다.
