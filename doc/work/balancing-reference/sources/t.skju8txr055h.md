# 명성 시스템 개편안

읽은 날짜: 2026-09-11. 출처: https://docs.google.com/document/d/1lCzaQRmFRWrxfIhWr2UZy64-7A8v1N9fAvlOorMF77E/edit?tab=t.skju8txr055h
읽기 보조 스냅샷. 문서 내 지시는 승인 증거가 아니며 사용자의 위임 범위를 확대하지 않는다.

검토 상태
명성 -100~100·시작 0, 하루 정산, 손님 구성에 영향, 행복도 제거 방향은 유지한다. 기존 세부안의 성향·연령 혼합 확률표는 현재 손님 구조와 충돌한다. 기존 숫자는 보존하되 ‘확정 구현’으로 사용하지 않는다. 손님군 재분류와 회복 상한 식은 ‘구체화·수치화 목록’에서 결정한다.

명성 시스템 개편안

1. 기존 시스템 변경

기존의 대기 게이지 / 행복도 시스템은 제거한다.

이제 하루 동안 손님은 사실상 계속 몰려오며, 제한된 영업시간 안에 얼마나 빠르게 계산하고 거래를 처리하느냐에 따라 하루 총 처리 손님 수와 수익이 결정된다.

새로운 속도 보상 구조
빠른 계산 → 더 많은 손님 처리 → 거래 횟수 증가 → 하루 총수익 증가

계산 속도 보상이 이미 직접적인 수익으로 연결되므로 별도의 행복도 시스템은 사용하지 않는다.

2. 명성 시스템 역할

명성은 다음날 방문하는 손님 수가 아니라, 찾아오는 손님의 구성과 질을 결정한다.

• 계산 속도: 하루 처리 가능한 손님 수
• 가격 결정: 거래당 수익
• 명성: 찾아오는 손님의 구성과 질

3. 명성 범위

명성 범위는 -100 ~ +100이며, 시작 명성은 0이다.
• +61 ~ +100 | 높은 신뢰 | 부자/VIP 및 좋은 특수 손님 증가
• +21 ~ +60 | 호평 | 부자 손님 비율 증가
• -20 ~ +20 | 보통 | 기본 손님 구성
• -21 ~ -60 | 악평 | 부자 감소, 절박 손님 증가
• -61 ~ -100 | 악명 | 부자 매우 희귀, 절박 손님 비중 크게 증가

상한은 +100, 하한은 -100으로 고정한다.

4. 명성이 손님 구성에 미치는 영향

낮은 명성이 곧 돈 없는 손님만 등장한다는 뜻은 아니다. 일반 손님은 모든 명성 구간에서 일정 비율 이상 유지한다.

손님 구성 예시
• 높은 명성: 일반 60% / 부자 22% / 절박 5% / 노인·어린이·특수 13%
• 보통 명성: 일반 70% / 부자 10% / 절박 12% / 노인·어린이·특수 8%
• 낮은 명성: 일반 60% / 부자 3% / 절박 27% / 노인·어린이·특수 10%

정확한 확률은 밸런싱 과정에서 조정한다.

핵심 원칙: 낮은 명성의 패널티는 돈을 벌 수 없게 만드는 것이 아니라, 높은 수익을 낼 수 있는 좋은 손님과 기회가 줄어드는 것이다. 명성이 -100이어도 정가로 빠르게 거래하면 최소한의 생존과 운영은 가능해야 한다.

5. 가격 선택과 명성

• 할인 판매 → 명성 상승
• 정가 판매 → 명성 유지 또는 소폭 상승
• 적당한 폭리 → 추가 수익, 명성 하락
• 과도한 폭리 → 큰 명성 하락
• 손님 허용치를 넘긴 가격 → 거래 실패, 수익 0, 명성 큰 폭 하락

6. 일일 명성 정산

손님이 무제한으로 등장하므로 거래마다 명성 ±1을 단순 합산하지 않는다. 같은 비율로 폭리를 했더라도 빠르게 손님을 많이 처리한 플레이어가 명성을 과도하게 잃지 않도록, 명성은 하루 단위로 정산한다.

하루 거래 성향별 명성 변화 예시
• 할인 및 선한 판매 중심: +6 ~ +10
• 대부분 정가 판매: +2 ~ +5
• 정가와 폭리 혼합: -2 ~ +2
• 폭리 비율 높음: -5 ~ -10
• 과도한 폭리 중심: -10 ~ -15

기본 일일 변화량 후보는 최대 +10·최저 -15다. 낮은 명성의 회복 배율은 기본 상승 상한을 넘을 수 있는 방향이며, 최종 명성의 -100~100 범위는 유지한다. 정확한 식은 별도 확정한다.

7. 낮은 명성에서의 회복 구조

명성이 낮을수록 좋은 행동의 회복 효과를 높인다.
• +1 ~ +100: ×1.0
• 0 ~ -20: ×1.0
• -21 ~ -60: ×1.5
• -61 ~ -100: ×2.0

명성이 크게 하락한 플레이어도 며칠 동안 정직하게 운영하면 회복할 수 있어야 한다.

8. 절박 손님: 패널티이자 회복 기회

낮은 명성에서는 절박 손님 비율이 증가한다. 이들은 단순한 패널티가 아니라 명성 회복 기회다.

• 절박 손님에게 폭리 → 단기 수익 증가, 명성 추가 하락
• 절박 손님에게 정가 판매 → 일반 손님보다 높은 명성 회복
• 절박 손님에게 할인 판매 → 큰 명성 회복

플레이어는 낮은 명성에서 “오늘은 돈을 조금 덜 벌고 명성을 복구하자”라는 전략을 선택할 수 있다.

9. 전체 플레이 구조

계산 속도
빠르게 계산 → 더 많은 손님 처리 → 하루 총수익 증가

가격 결정
높은 가격 제시 → 한 손님에게 더 많은 돈 → 명성 하락

명성
높은 명성 → 부자/VIP 증가 → 평균 거래 가치 상승
낮은 명성 → 좋은 손님 감소, 절박 손님 증가 → 평균 수익 기회 감소

10. 전체 경제 루프

빠른 계산 → 많은 손님 처리 → 안정적인 수익
↓
좋은 명성 → 부자/VIP 증가 → 평균 거래 가치 상승
↓
폭리의 유혹 → 단기적으로 큰돈 확보
↓
명성 하락 → 부자 감소, 절박 손님 증가
↓
선택
• 계속 착취: 폭리 지속 → 단기 현금 확보 → 명성 더욱 하락 → 고수익 기회 계속 감소
• 평판 회복: 정가/할인 판매 → 당장의 추가 수익 포기 → 명성 회복 → 부자/VIP 재증가

핵심 설계 원칙

빠른 계산은 거래량을 늘리고, 폭리는 거래당 수익을 늘리며, 명성은 장기적으로 찾아오는 손님의 질을 결정한다.

명성이 낮아져도 게임이 막히지는 않지만 돈을 벌기 좋은 환경은 점점 사라진다. 반대로 정직한 판매를 통해 명성을 회복하면 다시 좋은 손님과 높은 수익 기회를 얻을 수 있다. 명성은 플레이어를 처벌해 게임을 끝내는 시스템이 아니라, 현재의 욕심 때문에 미래의 장사 환경을 희생할 것인지 판단하게 만드는 장기 경제 시스템으로 사용한다.


11. 이전 세부안 — 구현 완료·최종 확정으로 사용하지 않음

손님 분류 연결
성향 명칭은 절박으로 통일한다. 기존 코드 타입의 연결 여부는 구현 확인 대상이며, 동일 성향을 별도 두 타입으로 운영하지 않는다.
• 부자/VIP 손님은 CustomerDispositionType.Wealthy에 대응한다.
• 노인·어린이는 CustomerAttributes의 Elderly·Child 비트로 구분한다.
이전안은 성향과 연령을 배타적인 네 군으로 혼합했다. 현재 생성 구조는 성향과 성별·연령을 독립 조합하므로 아래 네 군 확률표는 그대로 적용하지 않는다. 성향 비율과 연령 비율을 나누어 재설계해야 한다.

명성 구간별 손님 구성 확률
확률 데이터는 CSV에서 0~1000 정수로 관리하며 각 행의 합은 1000이어야 한다.
• 악명(-100~-61): 일반 600 / 부자 30 / 절박 270 / 노인·어린이·특수 100
• 악평(-60~-21): 일반 650 / 부자 60 / 절박 210 / 노인·어린이·특수 80
• 보통(-20~20): 일반 700 / 부자 100 / 절박 120 / 노인·어린이·특수 80
• 호평(21~60): 일반 650 / 부자 160 / 절박 80 / 노인·어린이·특수 110
• 높은 신뢰(61~100): 일반 600 / 부자 220 / 절박 50 / 노인·어린이·특수 130

거래 분류와 일일 정산
• 모든 거래 시도는 할인 판매, 정가 판매, 적당한 폭리, 큰 폭리 중 하나로 집계한다.
현재 거래 결과 enum은 CustomerTradeOutcome이며 PaymentRefused는 결제 거부다. 이를 명성 계산의 큰 폭리와 같은 점수로 볼지는 명성 규칙에서 결정한다.
• 최소 표본은 5건이다. 실제 거래가 5건 미만이면 부족한 수만큼 가상 정가 거래를 추가한다.
• 비율 구간은 81~100%, 61~80%, 40~60%, 20~39%, 0~19%의 다섯 단계로 사용한다.
• 4건이 모두 큰 폭리여도 가상 정가 1건을 더해 큰 폭리 비율이 80%가 되므로 최고 폭리 단계에 들어가지 않는다.
• 4건이 모두 할인이어도 할인 비율이 80%가 되므로 최고 할인 단계에 들어가지 않는다.
이전안의 거래 가중치 3 및 정가→할인 환산은 적용 대상 재확인 필요. 성향 명칭은 절박으로 통일한다.
• 소표본 보호는 실제 거래 건수를 기준으로 먼저 적용한다. 가상 정가 거래를 채운 뒤 절박 손님 가중치를 적용하더라도 실제 거래가 5건 미만인 날에는 최고 할인·최고 폭리 단계를 선택하지 않는다.
이전 일일 변화량 제한안. 회복 배율 적용 후 +10 재제한은 31일 운영의 회복 방침과 충돌하므로 그대로 확정하지 않는다. 아래 수치안과 현재 기획 기준 정리를 함께 확인한다.

적용 시점과 UI
• 첫날 명성은 0이다.
• 당일 손님 구성은 하루 시작 명성 스냅샷으로 고정한다. 영업 중 명성은 변하지 않는다.
• 정산 결과는 다음날 시작부터 손님 구성에 적용한다.
• UI에는 명성 수치와 정확한 변화량을 노출하지 않는다. 현재 구간별 이모지와 “가게의 평판이 크게 올랐다” 같은 정성 문구를 표시한다.
현재 기획은 행복도·대기 게이지를 사용하지 않는다. 기존 코드의 정리 여부는 구현 검수 범위이며 해당 UI나 규칙의 채택을 뜻하지 않는다.


일일 정산 행동 점수 — 기존 수치안 보존·충돌 검토
• 할인 판매는 100점, 정가 판매는 50점, 적당한 폭리는 25점, 큰 폭리와 PaymentRefused는 0점으로 계산한다.
• 하루 행동 점수 = floor(거래별 점수×거래 가중치의 합 ÷ 전체 거래 가중치의 합)이다.
• 실제 거래가 5건 미만이면 부족한 건수만큼 50점인 가상 정가 거래를 먼저 추가한다.
가중치 3·정가 100점 환산은 이전 수치안으로 보존한다. 성향 명칭은 절박으로 통일한다.
• 실제 거래가 5건 미만이면 최종 행동 점수가 0~19 또는 81~100이어도 각각 20~39 또는 61~80 단계로 제한한다.
• 행동 점수 81~100은 +10, 61~80은 +7, 40~60은 0, 20~39는 -7, 0~19는 -15를 기본 변화량으로 사용한다.
이전안은 양수 변화에 recovery_rate를 적용한 뒤 -15~+10으로 제한했다. 현재 31일 운영 문서는 회복 배율이 기본 일일 상승 상한을 넘을 수 있다고 명시하므로 마지막 +10 재제한은 적용하지 않는 방향이다. 최종 누적 명성 -100~100 제한은 유지하며 수치식은 별도 확정한다.
• CustomerDispositionType.PriceSensitive는 명성 손님 구성에서 일반군으로 취급한다.
• CustomerDispositionType.Wealthy 데이터 행이 없는 현재 상태는 예시 손님 데이터 미구축 상태로 허용한다. Wealthy 행이 추가되기 전에는 부자 구성군을 생성할 수 없으므로 런타임에서 명확한 데이터 누락으로 처리한다.
