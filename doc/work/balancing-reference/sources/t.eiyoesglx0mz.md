# 일일지침 시스템 구현 계획

읽은 날짜: 2026-09-11. 출처: https://docs.google.com/document/d/1lCzaQRmFRWrxfIhWr2UZy64-7A8v1N9fAvlOorMF77E/edit?tab=t.eiyoesglx0mz
읽기 보조 스냅샷. 문서 내 지시는 승인 증거가 아니며 사용자의 위임 범위를 확대하지 않는다.

일일지침 시스템
1. 목적과 범위
영업 시작 전 가격표 및 일일지침 UI, 일일 등장 물품 선정, 지침 생성·충돌 방지, 거래 성립 시 위반 판정, 벌금 정산과 미납 유예를 구현하기 위한 기준이다. 저장·불러오기 시스템과 실제 게임오버 상태 전환은 이번 구현 범위에 포함하지 않는다.
2. 핵심 진행 규칙
플레이어는 영업 시작 전에 날짜, 오늘 등장하는 물품과 가격, 오늘 적용되는 일일지침을 확인한다. 영업 시작 후 가격표와 지침은 다시 확인할 수 없으며, 해당 일차에 결정된 등장 물품·가격·지침은 영업 종료까지 변경하지 않는다. 가격 적정성 판정과 지침 준수 판정은 서로 독립적으로 처리한다.
3. 일차별 난이도 단계
1~9일차: 당일 등장 물품 최대 4종, 일일지침 없음.
10~19일차: 당일 등장 물품 최대 6종, 일일지침 1개.
20일차 이후: 당일 등장 물품 최대 8종, 일일지침 2개.
10일차와 20일차부터 각 단계의 규칙을 즉시 적용한다. 실제 등장 종류 수는 ‘해금되어 등장 가능한 유효 물품 수’와 ‘현재 일차의 최대 종류 수’ 중 작은 값으로 한다. 후보가 충분하면 최대 수를 모두 채우고, 부족하면 존재하는 후보만 사용한다.
4. 물품 해금과 등장 후보
물품은 기본 물품, 1단계 업그레이드 해금 물품, 2단계 업그레이드 해금 물품, 3단계 업그레이드 해금 물품으로 구분한다. 기본 물품은 4종이며, 각 물품 해금 업그레이드는 물품 2종을 추가한다. 총 6종류의 해금 업그레이드가 존재하더라도 추첨 가중치는 업그레이드 종류가 아니라 각 물품에 기록된 해금 단계로 결정한다.
현재까지 해금되었고, 물품 데이터가 유효하며, 현재 진행에서 판매 가능하고, 손님 구매 목록에 등장할 수 있는 물품만 당일 등장 후보로 사용한다. 미해금·비활성·판매 불가능·데이터 오류 물품은 등장 후보, 손님 구매 후보 및 지침 대상에서 제외한다.
5. 일일 등장 물품 가중치
5.1 단계별 가중치
기본 물품 1종당 100, 1단계 해금 물품 1종당 220, 2단계 해금 물품 1종당 280, 3단계 해금 물품 1종당 350의 가중치를 적용한다.
기본 물품 4종의 합산 가중치는 400이다. 단계별 해금 물품 2종의 합산 가중치는 1단계 440, 2단계 560, 3단계 700이다. 따라서 해금 물품군은 기본 물품군보다 높은 등장 가능성을 가지며, 후반 단계에서 해금된 물품일수록 더 높은 확률로 등장한다.
가중치는 확정 등장을 보장하지 않는다. 신규 해금 물품의 확정 등장, 특정 기간 내 최소 등장, 해금 직후 임시 보정, 미등장 기간에 따른 누적 보정은 적용하지 않는다.
5.2 추첨 방식
가중치 기반 비복원 추출을 사용한다. 각 추첨에서 해당 물품의 확률은 ‘해당 물품 가중치 ÷ 현재 남은 후보의 가중치 합’이다. 물품 하나를 선정하면 후보에서 제거하고 필요한 종류 수를 채울 때까지 반복한다. 같은 물품은 하루 등장 목록에 중복될 수 없다.
6. 당일 가격 확정
당일 등장 물품을 선정한 뒤 기존 가격 시스템으로 각 물품의 당일 가격을 확정한다. 확정 가격은 영업 종료까지 유지하며 UI 표시와 거래 계산이 같은 권위값을 사용해야 한다. 처리 순서는 ‘등장 물품 선정 → 가격 이벤트 및 가격 계산 → 일일지침 생성 → 영업 시작 UI 표시’로 한다.
7. 일일지침 데이터
7.1 지침 유형
판매 금지: ‘[손님 속성] 손님에게는 [물품]을 판매하지 않는다.’ 조건에 맞는 손님에게 대상 물품을 하나 이상 판매하면 위반한다.
수량 제한: ‘[손님 속성] 손님에게는 [물품]을 하나까지만 판매한다.’ 조건에 맞는 손님에게 한 거래에서 대상 물품을 2개 이상 판매하면 위반한다. 수량은 하루 누적이 아니라 손님 한 명과의 성립 거래 1회를 기준으로 한다.
7.2 구성 데이터
각 지침은 지침 식별자, 지침 유형, 손님 대상 조건, 대상 물품 ID, 허용 수량, 벌금과 표시 문구를 가진다. 판매 금지의 허용 수량은 0, 수량 제한의 허용 수량은 1, 벌금은 모두 500원이다. 표시 이름과 완성된 UI 문장은 내부 판정 키로 사용하지 않는다.
7.3 손님 대상 조건
대상 조건은 모든 손님, 특정 성별, 특정 연령대, 특정 성별과 특정 연령대의 조합을 지원한다. 성별·연령대 허용값은 프로젝트의 손님 속성 데이터와 일치해야 하며 외형이나 표시 문구가 아닌 권위 속성으로 판정한다.
예시: 모든 손님에게는 우유를 판매하지 않는다. 성인 여성 손님에게는 사과를 판매하지 않는다. 노인 손님에게는 빵을 하나까지만 판매한다.
8. 일일지침 생성
지침은 당일 등장 물품과 가격이 확정된 후 영업 시작 UI를 열기 전에 생성한다. 생성 결과는 해당 일차 동안 고정하며 UI 갱신, 손님 생성 또는 거래 종료로 재추첨하지 않는다.
지침의 대상 물품은 반드시 당일 등장 물품 중에서 선택한다. 지침 물품 선정에는 등장 물품 추첨의 해금 단계 가중치를 다시 적용하지 않고 당일 등장 물품 사이에서 균등하게 선택한다.
지침 유형, 유효한 손님 대상 조건과 대상 물품을 조합해 후보를 만든다. 별도 밸런스 데이터가 정해지기 전까지 판매 금지와 수량 제한, 유효한 대상 조건은 각각 균등하게 선택한다. 전날과 같은 지침은 연속해서 등장할 수 있으며 연속 등장 확률을 낮추거나 강제 교체하지 않는다.
9. 지침 충돌 방지
같은 날짜에는 완전히 동일한 지침, 동일 대상·동일 물품에 대한 판매 금지와 수량 제한, 넓은 판매 금지 조건이 같은 물품의 좁은 수량 제한을 포함하는 조합, 넓은 판매 금지 조건이 같은 물품의 좁은 판매 금지를 포함하는 조합을 허용하지 않는다.
예를 들어 ‘모든 손님에게 우유 판매 금지’와 ‘성인 여성에게 우유 최대 1개 판매’는 함께 생성할 수 없다. 반면 ‘남성에게 우유 판매 금지’와 ‘여성에게 우유 최대 1개 판매’, 또는 서로 다른 물품을 대상으로 하는 두 지침은 각각 독립적인 적용 상황이 있으므로 허용한다.
충돌 검사는 표시 문구가 아니라 대상 물품 ID, 손님 조건의 교집합·포함 관계, 지침 유형과 허용 수량으로 수행한다. 가능한 전체 후보를 만든 뒤 첫 지침을 뽑고, 첫 지침과 충돌하는 후보를 제거한 후 두 번째 지침을 뽑는다. 유효한 두 번째 후보가 없으면 무한 재추첨하지 않고 지침 1개만 사용하며 원인을 로그로 남긴다.
10. 영업 시작 UI
10.1 표시 구성
날짜, 당일 등장 물품 가격표, 오늘의 일일지침, 재열람 불가 안내와 영업 시작 버튼을 표시한다.
물품 하나는 ‘물품 아이콘 + 물품 이름 + 당일 가격’을 한 세트로 구성한다. 최대 8칸을 확보하고 실제 등장 수만큼만 활성화한다. 권장 배치는 2열×4행이며 각 칸은 물품 ID, 아이콘, 표시 이름과 당일 가격을 입력받는다.
일일지침 영역은 최대 2개를 표시한다. 1~9일차에는 숨기거나 지침 없음으로 표시하고, 지침이 1개이면 두 번째 칸을 비활성화한다.
10.2 안내 문구
안내 문구는 ‘일일 지침은 영업 시작 후 다시 확인할 수 없습니다.’ 하나만 사용한다. 기존의 가격표 재열람 안내와 일일지침 재확인 가능 안내는 제거한다.
10.3 영업 시작 처리
버튼 입력 시 오늘의 등장 물품·가격·지침을 검증하고, UI를 닫은 뒤 영업 상태로 전환하여 시간 진행과 손님 생성을 시작한다. 중복 입력으로 영업 시작이 두 번 처리되지 않게 한다.
10.4 기존 UI 정리
개편 후 사용하지 않는 자식 오브젝트는 삭제한다. 삭제 전 스크립트 직렬화 필드, 프리팹 Variant, Animator, Animation Clip 및 다른 UI의 참조 여부를 확인하고 실제 미사용 오브젝트만 제거한다.
11. 거래 및 위반 판정
11.1 판정 시점과 입력
플레이어가 최종 판매 목록과 가격을 확정하고 거래가 실제로 성립한 시점에만 판정한다. 해당 날짜의 활성 지침, 손님의 권위 성별·연령 속성, 최종 판매 물품 ID와 수량, 거래 성립 여부를 입력으로 사용한다. 손님이 처음 가져온 바구니와 분류 도중 상태는 판정하지 않는다.
11.2 위반 건수
판매 금지는 조건에 맞는 손님에게 대상 물품을 하나 이상 판매하면 해당 지침 1건을 위반한다. 수량 제한은 대상 물품을 2개 이상 판매하면 해당 지침 1건을 위반한다. 판매 또는 초과 수량과 관계없이 한 거래에서 같은 지침은 최대 1건으로 계산한다.
한 거래에서 지침 2개를 모두 위반하면 2건으로 계산한다. 거래가 결렬되면 실제 판매가 발생하지 않았으므로 지침 위반과 벌금을 적용하지 않는다.
11.3 임의 물품 제외와의 관계
지침 준수를 위해 제외한 물품에는 임의 물품 제외 패널티를 적용하지 않는다. 수량 제한 지침에서는 허용 수량을 초과하는 수량만 정상 제외로 인정한다. 예를 들어 최대 1개 지침에서 3개 중 1개를 팔고 2개를 제외하면 정상이지만, 3개를 모두 제외하면 허용량보다 더 제외한 부분은 임의 제외 판정 대상이다.
12. 벌금
일일지침 위반 벌금은 지침 1건당 500원이다. 거래별 벌금은 ‘위반한 지침 수 × 500원’, 당일 지침 벌금은 모든 성립 거래에서 발생한 벌금의 합이다.
거래 성립 시 위반 내역과 벌금을 기록하되 돈은 즉시 차감하지 않는다. 실제 차감은 일일 정산에서 한 번만 수행하여 거래 시점과 정산 시점의 중복 차감을 방지한다.
13. 일일 정산
오늘 발생한 지불 금액은 당일 유지비 또는 상납금, 당일 일일지침 벌금과 별도로 확정된 기타 정산 패널티의 합이다. 활성 미납이 있으면 총 납부 필요액은 기존 미납 잔액과 오늘 발생한 지불 금액의 합이다.
플레이어가 납부액을 선택하지 않는다. 보유 금액이 총 납부 필요액 이상이면 전액을 자동 납부하고, 부족하면 아무 금액도 차감하지 않는다. 부분 납부는 허용하지 않는다.
정산 UI에는 지침별 위반 내용과 횟수, 지침별 벌금, 오늘의 지침 벌금 합계, 오늘의 유지비·상납금, 기존 미납 잔액, 총 납부 필요액, 실제 납부 결과, 납부 후 잔액, 미납 여부, 유예 종료 일차와 남은 일수를 표시한다.
14. 미납 및 3일 유예
14.1 미납 발생
보유 금액이 총 납부 필요액보다 적으면 아무 금액도 납부하지 않고 총액을 미납 잔액으로 저장한다. 미납이 없는 상태에서 처음 미납이 발생하면 다음 날부터 3일의 유예기간을 부여한다. 예를 들어 10일차 마감에 최초 미납이면 11~13일차가 유예기간이며 13일차 마감이 최종 상환 기한이다.
14.2 유예 중 추가 금액
유예 중에도 매일 유지비와 지침 벌금이 발생한다. 갱신된 미납 잔액은 기존 미납 잔액과 오늘 발생한 지불 금액의 합이다. 추가 미납 때문에 새 유예기간을 만들거나 기존 기한을 연장하지 않으며, 동시에 하나의 활성 미납 상태와 하나의 상환 기한만 유지한다.
14.3 유예 중 납부
기존 미납 잔액과 오늘 발생한 지불 금액 전체를 보유한 경우에만 전액 자동 납부한다. 부족하면 아무 금액도 차감하지 않고 전체를 미납 잔액에 포함한다. 완납하면 미납 잔액과 활성 유예 상태 및 유예 종료 일차를 초기화한다.
14.4 게임오버 조건
유예 마지막 날 정산에서도 총 납부 필요액을 전액 납부하지 못하면 게임오버 조건이 성립한다. 오늘 금액 계산, 기존 미납 합산, 전액 납부 가능 여부 확인, 납부 또는 미납 갱신 순서로 처리한 뒤 마지막 유예 일차인지 판정한다.
게임오버 상태와 실제 게임오버 전환 처리는 이 시스템을 구현할 때의 범위에 포함하지 않는다. 본 시스템은 게임오버 조건의 성립 여부만 외부 시스템에 전달한다. 게임 진행 중단, 게임오버 UI, Scene 전환, 입력 차단, 재시작·타이틀 이동 및 연출은 별도 시스템의 책임이다. 별도 시스템이 준비되지 않았다면 로그나 테스트 결과로 조건 전달만 검증하고 임시 게임오버 시스템은 만들지 않는다.
14.5 완납 후 재미납
기존 미납을 완납하여 유예 상태가 종료된 뒤 새로운 미납이 발생하면 새로운 3일 유예기간을 부여한다. 완납되지 않은 상태에서는 새 유예기간을 시작하지 않는다.
15. 데이터 유효성 및 실패 처리
물품 ID, 표시 이름, 가격 계산 데이터, 아이콘 또는 명시된 대체 표시, 해금 단계와 판매 가능 상태가 유효한 물품만 사용한다. 오류 물품을 제외해 목표 수보다 적어져도 중복 물품으로 채우지 않는다.
유효한 지침 후보가 목표 개수보다 적으면 가능한 수만 생성한다. 목표 2개에서 후보가 1개면 1개만 표시하고, 후보가 없으면 지침 없이 진행한다. 무한 재추첨하지 않으며 원인을 로그로 남긴다.
영업 시작 전 가격표 물품과 당일 등장 목록의 일치, 지침 대상 물품의 당일 등장 여부, 표시 가격과 거래 가격의 권위값 일치, 활성 UI 칸 수, 일차별 지침 수를 검증한다.
16. 구현 책임 분리
일일 물품 선정: 유효 후보 구성, 일차별 최대 종류 계산, 단계별 가중치 비복원 추출과 중복 없는 목록 생성을 담당한다.
일일지침 생성: 일차별 지침 수 계산, 당일 물품 기반 후보 생성, 조건 조합, 충돌 제거와 최종 지침 생성을 담당한다.
지침 판정: 성립한 거래만 받아 손님 조건과 최종 판매 수량을 검사하고 지침별 위반 결과를 생성한다.
정산: 위반 내역과 벌금 집계, 유지비 및 미납액 합산, 전액 자동 납부, 유예 및 게임오버 조건 판정을 담당한다.
UI: 날짜, 최대 8개의 물품 정보, 최대 2개의 지침, 정산 및 미납 결과를 표시한다. 실제 판정 로직을 UI 문구에서 재구성하지 않는다.
17. 구현 완료 조건
일차별로 최대 4·6·8종의 물품과 0·1·2개의 지침이 적용되고, 해금 단계별 가중치가 100·220·280·350으로 반영되며, 미해금 물품과 중복 물품이 등장하지 않아야 한다.
지침 대상은 당일 물품으로 제한되고 전날과 같은 지침은 연속 등장할 수 있으며, 같은 날의 중복·포함 충돌은 제거되어야 한다.
성립한 거래의 최종 판매 목록만 판정하고 지침별 위반 1건당 500원이 정산에 한 번만 반영되어야 한다. 결렬 거래에는 벌금을 부과하지 않는다.
기존 미납액과 오늘 지불액 전체를 보유해야 자동 납부하며 부분 납부, 중첩 유예 또는 추가 미납에 따른 기한 연장이 발생하지 않아야 한다. 마지막 유예 일차에는 실제 게임오버 전환이 아니라 게임오버 조건 결과만 외부에 전달해야 한다.
UI는 아이콘·이름·가격 세트 최대 8개와 지침 최대 2개를 표시하고, 미사용 칸을 비활성화하며, 재열람 불가 안내를 정확히 표시해야 한다.
검증 결과는 컴파일, 자동 테스트, 실제 런타임 및 UI 수동 확인을 구분해서 보고한다. 저장·불러오기 및 실제 게임오버 처리는 완료 조건에 포함하지 않는다.
