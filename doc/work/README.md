# 작업 상태와 인계

담당 전환 또는 중단 시 다음 작업자가 이어갈 수 있는 최소 상태를 남긴다. 사람과 AI 도구 모두 같은 형식을 사용하며 매 작업마다 별도 파일을 만들 필요는 없다.

- 사람 담당자와 위임 범위를 기준으로 기록한다. 사용 도구·세션 링크는 보조 정보이며 권한 증거가 아니다.
- 기존 작업 명세·PR·이슈·인계 기록이 있으면 그곳을 갱신한다. 저장소에 별도 기록이 필요할 때만 이 폴더에 작업별 Markdown을 둔다.
- 영구 API·CSV·아키텍처 계약은 해당 기능 명세에 기록하고 여기에는 경로와 이번 차이만 남긴다.
- 완료 후 기록 보존·임시 인계 문서 정리는 [WORK_RULES.md의 병합 인계와 문서 정리](../WORK_RULES.md#병합-인계와-문서-정리)를 따른다. 미완료 작업이 참조하는 문서는 유지한다.
- 담당 전환이 승인 범위를 늘리거나 Git·외부 작업의 승인을 대신하지 않는다. 현재 checkout과 선행 파일을 다시 확인한다.
- 같은 파일·공용 계약을 두 담당자가 동시에 수정하지 않는다. 같은 Unity Editor의 조작·컴파일 유발 작업·테스트 실행 담당자는 한 번에 한 명만 지정하고 인계 때 기록한다.
- Temp의 XML·로그·화면은 다른 작업자의 환경에서 접근하지 못할 수 있다. 결과 요약과 기준 SHA·미커밋 범위·재실행 절차를 함께 남긴다. 원본 공유가 필요하면 승인된 위치와 권한을 먼저 확인하며 자동 업로드하지 않는다.

## 최소 인계 템플릿

필요한 항목만 채운다. 알 수 없는 값은 추측하지 않고 미확인으로 둔다.

```md
# 작업 상태: <작업명>

- 사람 담당자 / 위임받은 역할·범위:
- 사용 도구 / 보조 세션 링크(선택):
- 마지막 확인 시각(시간대 포함):
- 기준 저장소·브랜치·commit:
- 허용 경로 / 제외 범위:
- 보존할 미커밋·untracked 변경 / stash:
- 참조할 기능 명세·선행 산출물:
- 완료한 내용:
- 남은 작업:
- 장애·미확정·필요 승인:
- 다음 담당자 / 바로 할 행동:
- 동일 파일·공용 계약 편집 담당 / Unity Editor 조작 담당(해당 시):
- 검증: 실행 수·성공·실패·skip·미완료 / 증거 경로 / 미검증 범위:
- 검증 대상 SHA·미커밋 범위 / 재실행 절차 / 타 작업자 접근 가능 여부:
- Git: stage·commit·push·merge 각각의 실제 수행 여부:
```

`codex://` 등 도구 전용 링크만으로 인계하지 않는다. 링크를 열 수 없어도 위 상태와 저장소 파일로 작업 범위를 이해할 수 있어야 한다.
