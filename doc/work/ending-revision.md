## 기획의 확정 변경

- 시민권 구매 시 바로 엔딩을 판정한다. 기존의 구매 후31일차까지 영업 지속 규칙을 대체한다.
- 시민권 소지+도덕성 양수, 시민권 소지+도덕성 음수, 시민권 미소지, 유지비 미납을 구분한다.
- 시민권은 설비 상점 항목을 유지한다. 사용자 확인: 가게3단계 도달에 더해 1~3단계의 모든 상품·편의 설비와 가게 확장을 구매해야 한다.
- 연출은 대사 중심이며 우선 기존 엔딩 씬·리소스를 재사용한다.

## 확정 기준 / 산정 가정

- 확정: 시민권 제외 모든 상품·편의 설비와 가게 확장 보유. 현재 FacilityData12001~12011의11개, 선행 비용524,500G이며 시민권100만G 포함 총1,524,500G다(운영비 제외). 산정은 구매/보유 기준이며 일반 설비의 익일 활성일까지 시민권 구매를 대기시키는 별도 조건은 추가하지 않는다.
- 사용자 확정: 시민권 구매 당시 누적 도덕성0 이상은 긍정 엔딩, 0 미만은 부정 엔딩으로 분기한다.
- 대상 카탈로그 범위는 상품·편의 설비의 RequiredStoreStage<=3, 가게 확장의 TargetStoreStage<=3이며 시민권은 제외한다. 이후4~5단계 설비가 추가되어도 선행 조건에 자동 편입하지 않는다.
- 문서에서 변경하지 않은 시민권 가격100만G, 정산 중 구매, 미보유31일 최종 확인, 유지비 유예 만료 조건은 기존 규칙 유지로 산정한다. 단순 미납 발생과 유예 만료 게임오버를 혼동하지 않는다.
- 구매 즉시 종료하면 ‘31일 정산 전에 시민권 보유 시 미납 실패 면제’는 정상 새 게임에서 도달 불가능해진다. 이전 저장 데이터 이관은 저장 기능이 없으므로 범위 밖이며, 관련 정책·필드·설명·구형 테스트 제거/교체를 포함한다.

## 핵심 불변 조건

- 결제·소유권이 확정되기 전 엔딩을 만들지 않는다. 잔액 부족·단계 잠금·중복 구매는 엔딩을 만들지 않는다.
- 구매 도중 예약된 시민권 보유를 재진입 호출에서 완료 상태로 오인하지 않는다. 최상위 구매 요청이 지불·보유 확정과 종료 처리를 소유한다.
- FacilityService는 결제 후 알림 예외가 발생해도 지불·소유를 보존한다. 단순히 bool 반환값만 보거나 UI 성공 callback만으로 종료하면 예외 시 ‘시민권 소지 후 영업 지속’ 상태가 남으므로, 구매 상태와 종료 확정의 소유권을 GameProgress/GameSessionManager 경계에서 함께 검토한다.
- 구매는 기존 정산 시점에 허용하므로 경제 정산·딸 대사·일일 명성 적용을 두 번 하지 않는다. 마지막 명성은 기존 종료 경로와 같이 한 번 반영한다.
- 최종 snapshot에는 구매 직후 잔액·누적 도덕성·명성·종료일·소지 여부를 고정한다. 비동기 씬 이동 실패 시 판정·결제를 반복하지 않는다.
- 31일 최종 확인과 시민권 구매가 같은 입력 흐름에서 중복 종료를 만들지 않게 한다. 구매 종료 후32일 또는 다음 영업일을 생성하지 않는다.
- 신규 manager·저장 시스템·규칙 엔진을 만들지 않는다. MainScene 파일은 우선 유지하고 공용 prefab 연결 필요 시 최소 변경한다.

- 구현 담당자에게 Git 작업 금지를 전달했으나 `8c19aa5728a499df9b67437212a34bb950fbf140` 커밋과 `origin/codex/ending-revision` 푸시가 수행됐다. 원격 `ls-remote`로 확인하고 사용자에게 범위 밖 진행 사실을 알렸다. 이력을 임의 재작성하지 않았다. 이후 사용자가 `commit-push`를 요청해 남은 문서·가격 분석 자료의 커밋·푸시를 승인했다. 기본 브랜치 병합은 이번 요청에 포함하지 않는다.
- `104716` 실행은 결과 파일 미생성, `105916` 실행은 PlayMode 중단 로그와 결과 파일 미생성으로 미완료다. 완료되지 않은 실행을 PASS에 포함하지 않는다. 활성 테스트가 없음을 확인한 후 중단된 `105916` pending marker만 정리하고 최종 실행을 다시 시작했다.
