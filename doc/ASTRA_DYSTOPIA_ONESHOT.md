# 프로젝트 디스토피아 — Astra 원샷 제작 지시문

> 사용 방법: 이 파일을 Unity 프로젝트에 접근할 수 있는 Astra 세션에 첨부하고, “이 MD를 읽고 이미지 제작부터 Unity 구현·검증까지 진행해”라고 입력한다.
> 이 문서는 실행할 에이전트에게 주는 작업 지시문이다. 문서 작성만으로 이미지 생성이나 게임 구현이 완료된 것은 아니다.

---

## 1. 지금 수행할 작업

너는 이 프로젝트의 구현 담당 에이전트다. 아래 기획에 따라 **2D 픽셀아트 디스토피아 가격 기억 퍼즐 타이쿤의 플레이 가능한 프로토타입**을 만들어라. 기획 설명이나 코드 조각 제안으로 끝내지 말고, 접근 가능한 프로젝트에서 이미지 제작, 에셋 연결, 게임 구현, 실행 확인까지 수행하라.

목적은 모델 성능 시연이 아니라 **우리 게임이 어떤 느낌이며, 가격을 기억하고 압박 속에서 결정하는 행동이 재미있는지 직접 확인하는 것**이다. 설정 메뉴·복잡한 프레임워크보다 실제 거래 장면과 완결된 플레이 루프를 우선한다.

이 기획은 사용자가 정한 내용이다. 네가 새로 제안한 기획처럼 표현하지 말고 구현하라. 불명확한 수치는 아래 ‘프로토타입 임시값’을 사용하고, 확정 설정과 구분해 기록한다.

### 실행 원칙

- 이미 승인된 범위의 작업은 매 단계 확인을 요구하지 말고 이어서 진행한다.
- 시작할 때 환경과 기존 구조를 먼저 확인하고, 작업 위치·수정 파일·최소 변경 방법을 짧게 알린다.
- 기존 구현이 있으면 우선 활용한다. 관계없는 코드 정리, public API 변경, 대규모 리팩터링을 하지 않는다.
- 실행할 수 없는 도구, 생성하지 않은 이미지, 확인하지 않은 테스트를 성공했다고 쓰지 않는다.
- 기능을 하나씩 연결해 실제 동작을 확인하고 다음 단계로 진행한다.

## 2. 환경과 프로젝트 보호

기본 환경은 **Unity 6.3 LTS, 2D Sprite 기반 화면, PC 조작, 향후 WebGL 대응**이다. 실제 프로젝트 버전과 렌더 파이프라인을 확인하고 그 환경을 유지한다. 원샷 실행을 위해 Unity 버전·렌더 파이프라인을 임의 변경하지 않는다.

1. 적용되는 AGENTS.md, 현재 Git 상태, Assets 구조, 기존 진입점, 연결된 Unity 도구를 확인한다.
2. Unity CLI가 연결되어 있으면 해당 환경에 설치된 명령과 도움말을 확인하고 사용한다. 이미 연결된 Unity MCP도 필요할 때 활용한다. 명령이나 도구 존재를 추측하지 않는다.
3. 기존 팀 작업과 분리된 `Assets/DystopiaPrototype/` 아래에 신규 코드·데이터·아트를 만든다. 기존 경로와 충돌하면 고유한 하위 폴더를 선택한다.
4. **기존 Scene, Prefab, ProjectSettings, Packages, Library, UserSettings는 수정·삭제하지 않는다.** 기존 스크립트도 삭제하거나 통째로 교체하지 않는다. 사용자의 미커밋 변경을 보존한다.
5. 별도 프로토타입 진입 메뉴/Editor 도구를 추가해 새 임시 장면에서 런타임으로 화면을 구성하는 방법을 우선한다. 기존 장면을 저장하거나 덮어쓰지 않는다. 저장되지 않은 사용자 장면을 닫지 않는다.
6. 로컬 규칙이 신규 Scene/Prefab 생성까지 제한하면 그 규칙을 지킨다. 허용된 범위의 구현을 끝내고, 실행을 막는 정확한 제약과 필요한 최소 조치만 보고한다.
7. 패키지 설치 없이 기존 환경의 UI·Sprite 기능으로 구현하는 것을 우선한다. 유료 서비스 호출이나 외부 업로드를 임의로 추가하지 않는다.

## 3. 게임의 정체성

| 항목 | 내용 |
|---|---|
| 가제 | 프로젝트 디스토피아 |
| 장르 | 2D 가격 기억 퍼즐 타이쿤 |
| 배경 | 붕괴·전쟁 이후의 서울, 생필품을 파는 작은 배급소/가판대 |
| 시점 | 가판 안쪽 상인의 1인칭, 손님을 정면으로 마주 보는 고정 화면 |
| 핵심 행동 | 상품 가격 기억 → 상품과 수량 확인 → 총액 추정 → 받을 가격 결정 → 거래 |
| 압박 | 대기열 공통 대기 게이지, 매주 상납금, 안전구역 시민권 목표 |
| 갈등 | 더 많은 현금이 필요하지만 비싸게 받을수록 손님과 도덕성·명성에 부담 |
| 감정적 배경 | 화면 왼쪽 아래의 아픈 딸과, 안전구역으로 이동하려는 아버지 |
| 우선 완성 범위 | 거래·대기·명성·현금·정산·단일 목표 완료까지 연결된 짧은 플레이 |

딸은 세계관과 화면 연출에 포함한다. 딸의 체력·치료비 관리나 다중 엔딩은 이번 핵심 구현에 추가하지 않는다. 안전구역 시민권 가격은 최종 확정치가 아니므로 5억·6억을 고정 세계관 수치로 취급하지 않는다.

## 4. 필수 플레이 루프

`첫날 가격표 확인 → 영업 시작 → 손님 상품 확인 → 가격 입력 → 거래 판정 → 다음 손님 → 하루 정산 → 다음 날 → 주간 상납 → 시민권 구매`

### 4.1 가격 기억

- 첫날 영업 시작 전에 상품 가격표를 한 번 보여준다. 플레이어가 ‘영업 시작’을 누르면 닫힌다.
- 일반 플레이 중 가격표를 다시 열거나 상품별 정가·실제 총액을 보여주지 않는다. 손님도 정답 가격을 알려주지 않는다.
- 첫날 상품군에서 시작해 이후 상품 종류를 늘린다. 신규 품목은 처음 도입되는 날 영업 전에 신규 가격만 한 번 안내하는 임시 규칙을 사용한다.
- 이미 외운 상품의 정가는 유지한다. 날짜마다 임의 변경하지 않는다.
- 손님이 가져온 상품 그림과 수량은 분명히 확인할 수 있어야 한다.
- 숫자 입력 및 거래 확정, 지우기 기능을 제공한다. 마우스 조작과 숫자 키보드 입력을 모두 지원한다.
- 소수·음수·빈 입력·과도한 자릿수는 안전하게 처리한다. 확정 연타로 중복 거래가 발생하지 않게 한다.

### 4.2 거래와 손님

- 활성 손님은 한 명이다. 뒤에는 대기 손님이 보인다.
- 손님마다 구매 상품, 수량, 지불 가능 금액, 바가지 허용 범위가 있다.
- 실제 총액은 상품 정가 × 수량의 합으로 내부에서 계산한다.
- 제시 가격이 손님의 지불 가능 금액과 허용 범위 안이면 거래 성공, 현금 증가 후 다음 손님이 나온다.
- 예산이나 허용 범위를 넘으면 거부하고 떠난다. 현금은 늘지 않는다.
- 가난한 손님의 예산 부족을 이유로 한 거래 실패에도 **약간의 도덕성 하락**을 적용한다.
- 정가보다 싸게 주면 도덕성이 크게 오른다. 비싸게 팔면 도덕성이 내려간다.
- 명성은 대기 상태와 거래 결과를 반영하되, 높은 가격에 성공한 모든 거래가 무조건 거부와 동일한 큰 페널티를 받지는 않도록 한다.
- 대사는 짧게 표시한다. 가난한 손님에게 “집에 아이가 기다리고 있어요. 이것밖에 없는데…”와 같은 맥락을 주어 가격 결정에 감정적 이유를 만든다.
- 부자/VIP, 재방문 항의 등 독립된 특수 이벤트는 추가 기능으로 분리한다. 기본 손님 데이터의 예산·허용치 차이는 핵심에 포함한다.

### 4.3 대기 게이지·행복도·명성

**대기 게이지는 대기열 전체가 공유하는 하나의 값이다. 행복도와 별도 수치로 중복 구현하지 않는다.**

- 영업 중 시간이 지나면 감소하고, 정상 거래를 완료하면 증가한다. 빨리 처리할수록 높은 상태를 유지하기 쉽다.
- 손님별 개별 인내심 바를 여러 개 만들지 않는다.
- 초록 구간에서 거래를 완료하면 행복한 응대를 한 것으로 보고 명성을 올린다.
- 바닥나면 대기 중인 손님 일부가 이탈하고 명성이 내려간다. 프레임마다 반복 이탈하지 않도록 이벤트 후 회복 또는 쿨다운을 둔다.
- 대기 게이지/당일 행복 상태는 하루마다 초기화한다. 명성은 날짜가 바뀌어도 누적된다.
- 명성이 다음 날 방문객 수에 영향을 주게 한다. 높은 명성의 이점을 실제 손님 수로 확인할 수 있어야 한다.
- 안내창, 정산, 일시정지 중에는 대기 게이지가 줄지 않는다.

### 4.4 경제·상납금·목표

| 용어 | 사용 기준 |
|---|---|
| 정가 | 상품에 설정된 정상 판매 가격. 원가와 구분 |
| 실제 총액 | 손님 상품들의 정가 합계. 일반 영업 화면에서는 숨김 |
| 제시 가격 | 플레이어가 손님에게 요구하는 총 판매 금액 |
| 상납금 | 물품대금·임대료·감독관 뒷돈을 묶은 비용 |
| 감독관 | 매주 상납금을 걷고 안전구역 시민권 거래를 제시하는 인물 |
| 안전구역 | 최종 이동 목표인 보호된 거주 구역 |
| 명성 | 여러 날 누적되는 평판 |
| 도덕성 | 가격 결정과 약자의 사정에 대한 선택이 누적되는 값 |

- 상납 주기는 **매주**다. 일일 강제 납부와 혼동하지 않는다.
- 상납금은 진행에 따라 3단계로 증가한다.
- 물품대금이 상납금에 포함되므로 재고 구매비를 별도로 중복 차감하지 않는다. 정교한 재고 시스템도 핵심 범위에 넣지 않는다.
- 하루 종료 시 매출, 성공/거부 거래 수, 이탈 수, 명성 변화, 도덕성 변화, 보유 현금, 다음 상납일까지 남은 날을 표시한다.
- 납부일에 현금이 부족하면 명확한 실패 화면과 재시작을 제공한다.
- 시민권 구매 조건을 만족하면 구매 버튼으로 단일 완료 화면에 도달한다. 잔액과 당일 상납 순서를 명확히 처리한다.
- 감독관의 태도는 냉소적이고 위압적이다. 짧은 자막으로만 목표를 전달한다.

## 5. 프로토타입 임시값

아래는 바로 실행하기 위한 **조정 가능한 초기값**이다. 확정 기획으로 문서화하지 말고 한 설정 파일/데이터에 모아라. 계산이나 짧은 시뮬레이션으로 정상가 중심 운영 시 첫 상납이 가능한지 확인하고, 불가능하면 근거를 남기고 조정한다.

| 항목 | 초기값 |
|---|---|
| 총 상품 | 10종, 첫날 4종 → 3일차 7종 → 5일차 10종 |
| 손님 장바구니 | 초기 1~2종, 이후 최대 3종 / 각 1~3개 |
| 하루 | 기본 방문객 8명, 명성에 따라 6~12명; 해당 손님 처리/이탈 후 종료 |
| 대기 게이지 | 0~100, 매일 70 시작, 초록 구간 70 이상 |
| 감소·회복 | 초당 -2, 성공 거래 +12 |
| 게이지 바닥 | 대기 손님 최대 2명 이탈, 명성 -5, 게이지 30으로 회복 |
| 명성·도덕성 | 각각 0~100, 초기 50 |
| 초록 거래 명성 | 거래 회복을 적용하기 직전 게이지가 70 이상이면 +1 |
| 허용치 초과 거부 | 명성 -2, 도덕성 -1 |
| 예산 부족 거부 | 명성 -1, 도덕성 -1; 복합 실패에도 중복 차감하지 않음 |
| 할인 거래 | 정가 미만이면 도덕성 +2, 실제 총액의 80% 이하이면 +4; 둘을 중복 합산하지 않음 |
| 바가지 성공 | 정가 초과 성공이면 도덕성 -2 |
| 정가 거래 | 가격에 따른 도덕성 변화 0 |
| 손님 허용치 | 실제 총액의 110~150% 범위에서 유형별 설정 |
| 초기 현금 | 0원 |
| 상납금 | 7일차 50,000원 / 14일차 80,000원 / 21일차 이후 매주 110,000원 |
| 시민권 | 임시 300,000원, 상납 처리 후 구매 가능 |

상품 예시: 생수 1,000원, 건빵 1,500원, 통조림 2,500원, 즉석밥 2,000원, 붕대 3,000원, 진통제 4,000원, 건전지 3,500원, 비누 1,000원, 방진 마스크 2,000원, 연료캔 5,000원. 상품과 가격은 테스트용이며 데이터로 교체 가능하게 만든다.

손님 예산은 실제 총액을 바탕으로 생성하되 대부분은 정가 구매가 가능하고, 일부만 부족하도록 한다. 가난한 손님·보통 손님의 대사와 외형을 연결해 선택의 단서를 제공한다. 숨겨진 수치를 전부 UI로 노출하지 않는다.

## 6. 화면과 아트 방향

### 6.1 화면 구성

- **16:9**, 1280×720 이상에서 UI가 잘리지 않는 구성.
- 실제 배경·인물은 완전 2D 스프라이트, 상인 1인칭 정면 시점.
- 화면 아래쪽에 가판 상판, 중앙에 현재 손님 한 명, 뒤에 기다리는 손님들이 보인다.
- 가판과 손님 사이에 시야를 막는 높은 벽·격벽을 두지 않는다.
- 기본 가판 이미지는 상판이 비어 있어야 한다. 거래 상품만 런타임에 별도 스프라이트로 올린다.
- 화면 왼쪽 아래에 작고 귀여운 딸을 둔다. 플레이어 쪽을 보며 양팔을 들어 보이되 손·팔은 정확히 두 개다. 창백하고 지친 느낌을 주며 전체 분위기에 맞춘다.
- 딸이 가격표를 보거나 플레이어 조작 영역을 가리지 않게 한다.
- 플레이어 손은 보이지 않는다.
- 가격 입력 및 확정 영역은 오른쪽 아래 중심으로 배치한다. 보유금, 날짜, 공통 게이지 등 필요한 정보는 정돈된 HUD로 만든다.
- 아트 이미지 자체에 글자·메뉴·가방 버튼·가격표·UI를 그려 넣지 않는다. 필요한 한국어 UI는 Unity에서 구현한다.

### 6.2 색감과 표현

키워드: 붕괴 이후 서울, 회백색 콘크리트, 낡은 철판, 먼지, 차가운 흐린 빛, 저채도 청회색, 절제된 픽셀 명암.

- 가게 안과 밖 모두 어둡고 침울하다. 따뜻하고 아늑한 상점처럼 만들지 않는다.
- 인물과 물품은 플레이에 필요한 만큼 배경과 분리되게 한다. 어둡다는 이유로 상품을 알아볼 수 없게 하지 않는다.
- 참고 방향은 ‘안녕 서울’, ‘Kill the Shadow’에서 느끼는 도시 쇠락과 분위기다. 기존 게임 화면·캐릭터를 복제하지 말고 독자적인 에셋을 제작한다.
- 굵고 읽기 쉬운 픽셀 형태, 제한된 색상, 일관된 픽셀 밀도를 유지한다. 실사풍 인물·부드러운 3D 렌더·매끈한 일러스트를 피한다.
- 권장 월드 기준 해상도는 640×360. 큰 이미지로 생성됐다면 최근접 축소와 필요한 수정을 통해 맞추고, 단순 축소만으로 픽셀아트 완성이라고 간주하지 않는다.
- Sprite는 Point 필터, mipmap 비활성화, 동일한 PPU를 기본으로 한다. 프로젝트 전체 설정 변경 없이 신규 에셋 범위에서 조정한다.
- UI는 각진 단색 패널, 얇은 메탈 테두리, 흰 글자 중심이다. 둥근 모바일 카드·형광 그라데이션을 쓰지 않는다.

## 7. 이미지 제작까지 수행할 것

### 7.1 도구 확인과 제작 순서

1. 현재 세션에서 실제 사용 가능한 이미지 생성/편집 도구와 관련 스킬을 확인한다.
2. 가능하면 배경·가판·첫 손님·딸을 먼저 제작해 게임 화면에 연결하고 시각 기준을 고정한다.
3. 그 결과를 참고 이미지로 재사용해 나머지 인물과 상품의 스타일을 맞춘다.
4. 합성된 게임 스크린샷 한 장을 전체 배경으로 붙여 완료하지 않는다. 배경, 가판, 인물, 딸, 상품은 독립적으로 교체 가능한 에셋이어야 한다.
5. 생성 결과의 손·팔 개수, 외곽 잘림, 배경 혼입, 그림자 잔여물, 인물 크기, 원근을 확인하고 필요하면 수정한다.
6. 투명 PNG가 필요한 에셋은 실제 알파 투명도를 확인한다. 체크무늬가 그려진 그림을 투명 이미지라고 취급하지 않는다.
7. 이미지 생성 도구가 없으면 생성했다고 주장하지 않는다. 교체 가능한 임시 시각 에셋으로 플레이 구현을 끝내고, `ART_PROMPTS.md`에 아래 프롬프트와 필요한 규격을 정리한다. 최종 보고에 실제 이미지 제작 미완료를 명시한다.

### 7.2 최소 아트 목록

| 에셋 | 목표 | 조건 |
|---|---|---|
| 서울 배경 | 1장 | 16:9, 인물·전경 가판·글자 없음 |
| 가판 전경 | 1장 | 비어 있는 상판, 손님을 가리지 않는 낮은 구조, 투명 배경 |
| 일반 손님 | 우선 4개 완성 외형 | 정면 상반신, 동일한 기준선·크기, 투명 배경 |
| 추가 손님 외형 | 가능하면 조합 약 20종 | 머리·모자·옷·스카프 등 정렬된 파츠 조합; 안정적 합성이 가능할 때 확대 |
| 딸 | 기본 1장 | 작은 정면 인물, 양팔·양손 정확히 두 개, 투명 배경 |

첫 플레이를 위해 4개 손님 외형을 우선 연결하되, 이를 전체 아트 계획의 최종 인원으로 고정하지 않는다. 파츠 조합이 어색하면 먼저 완성형 스프라이트를 사용하고 파츠화는 추가 단계로 넘긴다.

### 7.3 생성 프롬프트

공통 스타일 문장을 각 프롬프트에 결합하고 최초 확정 이미지를 참조한다.

**공통 스타일**

> Original 2D pixel-art asset for a first-person dystopian street ration stall game in a ruined Korean city. Restrained coarse pixel clusters, consistent pixel density, desaturated gray and blue-gray palette, worn materials, cold overcast lighting, bleak oppressive mood, readable silhouettes. Not photorealistic, no smooth 3D rendering, no warm cozy lighting, no baked-in text, no UI, no watermark.

**배경**

> 16:9 background viewed from inside a low street vendor stall looking straight out toward a ruined Seoul alley. Weathered concrete buildings, damaged shutters, exposed pipes, distant barriers, cold dusty air. The central foreground must remain clear for a separately composited customer. Background only: no people, no counter, no objects in the foreground, no legible signage. Flat 2D pixel-art game environment with restrained depth.

**가판**

> Foreground counter asset from the vendor's first-person viewpoint. A low battered metal and wood ration-stall counter spanning the bottom of a 16:9 game screen. Broad completely empty tabletop, subdued gray surfaces, worn edges. No products, no monitor, no hands, no people, no tall partition between vendor and customer. Transparent background outside the counter silhouette.

**일반 손님**

> One adult civilian customer facing the viewer directly, upper body visible, neutral readable pose, arms naturally lowered. Worn layered clothes appropriate to a collapsed Korean city, tired restrained expression. Entire required silhouette inside the frame, consistent front view and lighting, transparent background, no environment, no counter. Create an original identity. Variation: [age / hair / coat / scarf / hat].

**딸**

> One small young daughter character for the lower-left corner of a first-person game screen, facing and looking toward her father, the viewer. Cute restrained pixel-art proportions, pale and slightly ill-looking, tired eyes, worn muted clothes, both arms gently raised toward the viewer. Exactly two arms and two hands. No injuries or gore, no price sheet, no items held, no text. Transparent background, entire silhouette within frame, same cold subdued lighting as the scene.

**상품**

> A single [item] inventory sprite for a bleak ration stall game, clearly recognizable at small size, simple distinct silhouette, consistent pixel density and subdued palette, front or slight top-front view suitable for resting on a counter. Transparent background, no words, no price label, no extra objects. Use a consistent canvas and visual scale across the full item set.

**감독관**

> One intimidating corrupt ration-district inspector, facing the viewer, upper body portrait, worn dark official coat, restrained smug expression, a bureaucratic rather than fantastical design. Original character, same desaturated pixel-art palette and scale as civilian customers, transparent background, no text or insignia requiring readable lettering.

## 8. 구현 구조와 조작

과도하게 분리하지 말고, 데이터와 판정·표시가 얽혀 수정하기 어려워지지 않을 정도로 구성한다. 다음 책임을 충족하면 파일명과 클래스 수는 기존 구조에 맞게 정한다.

- 상품/손님/밸런스 데이터.
- 날짜·현금·명성·도덕성을 보관하는 게임 상태.
- 가격·예산·허용치 판정을 수행하는 거래 로직.
- 공통 대기 게이지와 대기열 진행.
- 일일 정산·주간 상납·구매 목표 처리.
- 이미지·한국어 UI·입력·상태 전환을 연결하는 화면.
- 독립된 프로토타입 실행 진입점과 필요한 Editor 도구.

상태 전환은 최소한 가격 안내, 영업, 거래 결과, 정산, 상납, 목표 완료, 실패를 명시적으로 구분한다. 결과 연출 중에는 새 거래 입력을 차단하고, 거래 전후 타이머 처리 순서를 일관되게 유지한다.

숫자 키로 금액 입력, Backspace로 삭제, Enter로 확정, Escape로 일시정지를 기본으로 한다. 입력 필드 포커스와 단축키의 이중 입력을 막는다. 버튼은 마우스로도 사용 가능해야 한다.

한국어 글꼴이 이미 있으면 재사용한다. 없으면 로컬에서 사용 가능한 적법한 글꼴을 확인해 최소한의 적용 방법을 선택하고, 글리프가 네모로 나오는지 실제 확인한다. 보유하지 않은 폰트·에셋 경로를 만들어 참조하지 않는다.

세이브 시스템·네트워크·로그인·대형 인벤토리는 요구하지 않는다. 재시작은 모든 런 상태를 초기화해야 한다.

## 9. 추가 기능 — 핵심 완성 후에만

다음은 MVP Stretch다. 필수 기능처럼 한꺼번에 구현하지 말고 핵심 루프의 실행·검증이 끝난 후 여유가 있으면 한 가지씩 추가한다. 미구현이어도 핵심 프로토타입은 완결되어야 한다.

| 우선순위 | 기능 | 목적 |
|---|---|---|
| 1 | 운영 아이템과 일일 특가 | 돈을 더 벌어 사고 싶다는 욕구를 만들고 가격 결정에 유혹을 추가 |
| 2 | 특수 손님 | 부자, 예산 부족 사연, 과거 선택의 결과를 보여주는 재방문 등으로 운영 판단 변화 |
| 3 | 거래 규정 | 특정 요일 특정 물품 판매 금지 등 매일 지시문에 따른 판단 변화 |
| 4 | 가게 성장·연출 확대 | 파츠 손님 확대, 미세 애니메이션, 조명·환경 연출 |

운영 아이템을 넣는다면 먼저 결제 속도를 줄이는 장비 하나와 특가만 연결한다. “명성 축적 → 손님 증가 → 사고 싶은 장비 등장 → 돈 부족 → 비싸게 판매할 유혹 → 장비 구매 → 운영 효율 개선 → 명성 회복”이 실제로 발생하게 한다. 결제 지연 시간이 없는 구현에 효과 없는 속도 장비를 붙이지 않는다.

거래 규정은 가격 기억이라는 기존 루프를 확장한다. 경고 누적 3회 후 벌금, 일정 기간 후 초기화하는 방식은 후보 규칙이며 확정으로 취급하지 않는다. 지속 의심도와 경고 시스템을 동시에 기본 탑재하지 않는다.

## 10. 진행 순서

1. **환경 확인**: 기존 프로젝트와 실행 가능한 도구, 보호 규칙 확인.
2. **핵심 거래 구현**: 한 손님·한 상품으로 입력부터 현금 반영까지 동작.
3. **첫 화면 아트 연결**: 생성 가능한 경우 배경·가판·손님·딸을 제작하고 실제 화면에 배치.
4. **반복 플레이 연결**: 여러 상품과 손님, 공통 게이지, 이탈, 명성·도덕성 처리.
5. **런 완결**: 가격 안내, 날짜 진행, 정산, 주간 상납, 실패·시민권 완료·재시작.
6. **가독성·밸런스 수정**: 상품 식별, 입력 반응, 대기 압박, 정상 운영의 생존 가능성 확인.
7. **검증과 인계**: 실행 증거, 조작법, 테스트 결과, 실제 미완료 항목 기록.

진행 중 중요한 발견이나 장애가 있으면 짧게 알리되 계획 설명을 반복하지 않는다. 아트 생성 대기나 도구 장애로 전체 코드 구현을 멈추지 않는다.

## 11. 완료 판정과 검증

가능한 범위에서 Unity를 직접 실행하고 다음 항목을 확인한다. 실행 접근이 없다면 정적 검토와 실행 확인을 명확히 구분한다.

- [ ] 새 진입점으로 기존 팀 장면을 수정하지 않고 프로토타입에 들어간다.
- [ ] 첫날 가격표를 본 뒤 정답 가격을 보지 않고 거래할 수 있다.
- [ ] 여러 상품과 수량의 합계 계산이 정확하다.
- [ ] 정가/할인/허용 범위 내 바가지/예산 부족/허용치 초과 결과가 의도대로 다르다.
- [ ] 거래 확정 연타로 매출이나 손님 진행이 중복되지 않는다.
- [ ] 공통 게이지 감소·성공 회복·바닥 이탈이 작동한다.
- [ ] 정산과 일시정지 중 게이지가 멈추고, 다음 날 초기화된다.
- [ ] 명성·도덕성·현금은 날짜가 바뀌어도 유지된다.
- [ ] 명성에 따른 다음 날 방문객 수 변화가 작동한다.
- [ ] 7일차 상납, 현금 부족 실패, 시민권 구매 완료, 재시작을 확인한다.
- [ ] 새 게임으로 되돌아가면 이벤트 구독·UI·손님이 중복되지 않는다.
- [ ] 16:9 화면에서 버튼이 잘리지 않고 한국어와 상품을 읽을 수 있다.
- [ ] 생성 에셋의 투명도·픽셀 크기·손가락/팔 오류를 시각 확인했다.
- [ ] 신규 코드에 의한 컴파일 오류와 실행 예외가 없다.

날짜 이동·현금 지급·정답 표시가 필요한 검증 도구는 Editor/개발 모드에만 제공한다. 최종 일반 플레이 화면에 정답이나 디버그 버튼을 노출하지 않는다. 검증 때문에 프로덕션 판정 로직을 우회하지 않는다.

가격 판정 경계와 주간 납부처럼 오류가 결과를 바꾸는 부분은 필요한 최소 자동 검증을 추가할 수 있다. 단순 UI 배치나 구현을 그대로 복사하는 테스트를 늘리지 않는다. PC 실행 확인 없이 WebGL 대응 완료라고 주장하지 않는다. WebGL 빌드는 환경과 기존 설정이 허용될 때 수행하고 결과를 별도 보고한다.
